MINECRAFT-AI MODPACK MANIFEST
=============================
Target Minecraft version: 1.21.11 (Fabric)
Purpose: record of every mod/datapack to install when a game profile is
created (launcher instance, server pack, etc.). This file is a plan/reference,
not something the "aibot" mod reads at runtime.

--------------------------------------------------------------------------
REQUIRED RUNTIME
--------------------------------------------------------------------------

- Minecraft 1.21.11
- Java 21 or newer (the launcher's bundled Java 21 works)
- Fabric Loader 0.18.4 or newer (0.19.5 is the current stable build)
  https://fabricmc.net/use/installer/

--------------------------------------------------------------------------
THIS PROJECT'S OWN MODS (install into the profile's "mods" folder)
--------------------------------------------------------------------------

1. Fabric API
   Version: 0.141.6+1.21.11
   https://modrinth.com/mod/fabric-api
   Required by the aibot mod (see fabric.mod.json "depends"), and by nearly
   every mod below.

2. AIBot / Minecraft-AI (this project)
   File: Minecraft-AI-<mod_version>.jar, built from this repo
   (gradlew build, then build/libs/Minecraft-AI-*.jar; bash scripts/deploy_profile.sh
   builds it and installs it into a profile, see docs/DEPLOY_LOCAL.md). In-game the
   mod displays as "Minecraft-AI" with no author (renamed 2026-09-27 to drop the
   attribution left over from the zoyluo/mc_aiplayer fork this project started from).
   Requires Fabric API (#1).

3. PvP BOT Inhabitants
   File: pvpbot-inhabitants-<version>.jar, built from
   C:\Users\PC\Desktop\Minecraft-Spawn-Bots-Wrapper (a separate local repo)
   (gradlew build, then build/libs/pvpbot-inhabitants-*.jar).
   Standalone addon that populates registered structures (POIs) with
   randomized PvP BOT inhabitants; does not modify or bundle PvP BOT itself.
   Requires Fabric API (#1), PvP BOT (below) and HeroBot (below).
   Privacy: PvP BOT sends anonymous bot/damage stats to an external server
   over plain HTTP by default; this profile disables that
   ("send_anonymous_statistics": false in config/pvpbot/stats_config.json,
   set after the first server start generates the file). This addon itself
   sends no telemetry.

FirstPerson (2.7.2-1.21.11, "enables the third-person model in first-person")
was removed 2026-09-27 by the user's own preference.

Complementary Unbound is a shaderpack: it goes in the profile's
"shaderpacks" folder, not "mods", and needs Iris (above) to select it
(Options > Video > Shaderpack Selection). Euphoria Patches, despite the
name, is a regular mod (goes in "mods") that patches Complementary at
runtime -- it does nothing without Complementary Unbound + Iris installed.

Bumped r5.7.1/1.8.5 -> r5.9.3/1.10.5 on 2026-09-27: the old pair (8 months
old, 5 point-releases behind) failed to compile its final.fsh shader
("undefined variable") on this profile's exact combo -- the very next
upstream release's changelog fixes the same class of bug ("X not declared
compile error"), so this was an upstream bug, not a broken install. Old
shaderpack folder and old Euphoria jar removed.

The shaderpack is kept as an EXTRACTED FOLDER, not the .zip Modrinth ships:
on first launch after installing the zip, Iris auto-extracts it (Euphoria
Patcher has to inject its own additional files into individual shader
sources, which it can't do inside a zip) into a same-named folder -- so a
zip left sitting alongside its own auto-extracted folder shows up as two
separate entries in Iris's shaderpack list, which is confusing and the
extracted copy has more files than the zip anyway (634 vs 468: Euphoria adds
its own properties/lang files on top of Complementary's). Delete the zip
after that first launch and point config/iris.properties' shaderPack at the
folder name instead, so only one entry ever shows up.

Fiw Graves (by Fi3w0) replaces DeathMarker (below): server-side/singleplayer
grave system, packet-only marker+hologram at your death spot (nothing written
to the world, so it can't leak or crash-corrupt), 10-minute despawn with
quick-collect, and an admin loot-backup safety net (`/graves rollback`,
`/graves restore`) beyond vanilla's normal item despawn. No client jar
involved, so it isn't exposed to the client-rendering API break that killed
DeathMarker. https://modrinth.com/mod/fiw-graves

DeathCompass (by Nikrecs) stacks with Fiw Graves: on respawn it puts a
lodestone-targeted compass pointing at your last death spot straight into
your inventory (drops at your feet if the inventory is full). Zero config,
server-side/singleplayer, requires Architectury API (below, added alongside
it) plus Fabric API (already installed).

DeathMarker (v1.0.0-1.21-fabric) was removed 2026-09-27: it crashes the client
on load (NoClassDefFoundError on Fabric API's WorldRenderEvents). Its only
Fabric build is compiled against a much older Fabric API (its GitHub source
targets 1.20.1 / fabric_api_version 0.92.7); Minecraft's client rendering
internals moved on by 1.21.11 and the mod (last updated 8 months ago, no
GitHub releases) was never rebuilt against a newer one. Re-add it if/when the
author (LumaBlossom) publishes a 1.21.11-compatible build.

(PvP BOT itself is listed under World Generation / Exploration above, since
that is what it primarily adds; it is a gameplay/combat mod too.)

Better Name Visibility requires YetAnotherConfigLib (YACL) -- added under
Inventory / UI / QOL below; it was missing from the original list and would
have failed to load without it.
